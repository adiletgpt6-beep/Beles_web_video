# Инструкции для агентов Beles

Перед работой прочитайте START_HERE.md и перечисленные там актуальные файлы. Они обязательны для ChatGPT/Codex и других агентов.

- Истина о стиле, утверждениях, файлах и прогрессе хранится в GitHub.
- Последний ролик V5 утверждён пользователем. Сохраняйте его темп и бело-голубые субтитры без общей подложки.
- Не считайте пример zeket.kg обязательным содержанием каждого нового ролика.
- До выдачи короткого промпта Claude Code исходник должен быть действительно загружен и доступен из репозитория/Release, а размер и SHA-256 — проверены. Локальный путь и ссылка на вложение ChatGPT не заменяют доставку.
- Не выдавайте выполненный документальный этап за завершённую загрузку или готовый монтаж.
- Перед длительным этапом и передачей контекста обновляйте production/HANDOFF.md и production/STATE.json: сделано, проверено, следующий шаг, ограничения, ветка/пути.
- У каждого нового ролика нужен отдельный ID и каталог; не подменяйте материалы старого задания.
- Команды процесса — `python3 scripts/beles.py queue/next/status/ingest/restore/verify/checkpoint/sync` (подробности INGEST.md). Manifest и checkpoint задания — первичные данные; HANDOFF/registry восстанавливаются через sync.
- Новый материал сначала staged; queued — после публикации и restore + verify --record-delivery в независимом GitHub clone. Опубликуйте delivery/checkpoint перед коротким промптом Claude. Локальный commit сам по себе не подтверждает удалённую доставку.
- BW-001 закрыт как approved_baseline. BW-002 не создавать без настоящей новой съёмки; интеграционные тесты используют только временные репозитории.
- Не запускайте платные API/платные runners автоматически. Пользователь чувствителен к расходам.
- Не перезаписывайте утверждённый эталон и не меняйте историю Git. Перед обновлением ветки повторно проверяйте её head.
