# Beles — простой процесс: Studio → скриншот → GitHub → Claude Code

## Для пользователя (4 действия)
1. Загрузить видео в BalaGo Studio, выбрать целевой репозиторий и нажать «Отправить в работу» **один раз**.
2. Сделать скриншот выданного ID (VID-XXX или LIVE-XXX) и прислать ChatGPT. Номер на экране — ID Studio, **не** BW-ID Beles.
3. ChatGPT проверяет реальную запись Studio/GitHub, находит существующую загрузку, связывает её с единственным BW-ID в Beles, записывает полный production brief, ограничения, ссылки, хеши, checkpoint и короткую команду. Если уже зарегистрировано — переиспользует ID, без дублей.
4. Пользователь отправляет Claude Code **только** короткую команду. Claude самостоятельно читает GitHub, получает оригинал через защищённый Studio broker, проверяет файл, делает монтаж и QA, сохраняет код/MP4/превью/отчёт в GitHub и возвращает ссылки.

## Короткий промпт для Claude Code
`Выполни Beles BW-XXX до готового проверенного MP4. Репозиторий adiletgpt6-beep/Beles_web_video, начни с START_HERE.md. Полное ТЗ и исходник — по manifest/HANDOFF задания. Сохрани результат и ссылки в GitHub. Не запускай платные API или платные runners.`

## Постоянные правила
- Studio ID (VID/LIVE) и BW-ID — разные идентификаторы. Нельзя угадывать соответствие только по скриншоту; сверить Studio uploadId, GitHub Issue/metadata, repository и исходный manifest. Не создавать BW-дубликаты по uploadId/SHA.
- Не путать отправленный Studio исходник с доставленным Claude: до фактического SHA-256/ffprobe не отмечать delivery_verified.
- Для submitted Studio видео использовать уже существующий source broker, не повторять upload и не создавать Issue вручную. Не копировать приватные подписанные URL/токены в GitHub.
- Полный промпт (сценарий по реальной речи, концепция, монтаж, QA, публикация) живёт в `production/jobs/BW-XXX/brief.md` и manifest; короткая команда не дублирует его.
- Каждый рекламный ролик визуально уникален при сохранении качества V5, проверка кыргызских субтитров (ө/ү/ң), WhatsApp 0998 08 38 28. Реальные сайты показывать только по правилам WEBSITE_SHOWCASE_RULES.
- Claude может автоматически выполнить бесплатные локальные шаги монтажа после явной команды пользователя; платные API/Actions/runners — только после отдельного согласия. Если ресурс или разрешение недоступны — сохранить checkpoint и сообщить блокер, а не объявлять MP4 готовым.
- BW-001 не менять; BW-002 и BW-003 уже зарегистрированы, не создавать их заново.

## Техническая связка Studio Issue → Beles (добавлено 2026-11-05)

Новые Studio VID Issue содержат точные поля: `Репозиторий`, `Ключ R2`, `Upload ID`, `Размер (байт)`, `SHA-256`, скрытый `studio-upload-id`. Studio PR #176 опубликован в main (коммит `a68a508`).

После получения скриншота VID-XXX ChatGPT должен найти **существующий GitHub Issue** в `adiletgpt6-beep/Beles_web_video`, проверить поля и сохранить полный монтажный brief в Beles. В локальном клоне можно использовать `python3 scripts/beles.py register-studio-issue /tmp/studio-issue-body.md --brief "Полное ТЗ"`, где файл содержит точное тело Issue из GitHub. Скрипт создаёт BW-ID с защитой от повторной регистрации по SHA/uploadId. Затем записать полный brief.md, checkpoint и коммит; выдать пользователю только BW-ID и короткую команду Claude. Никогда не регистрировать видео по одному только номеру из скриншота без проверки Issue.

Studio ID VID-XXX не равен BW-ID. Исходник остаётся в R2; для нового submitted VID source broker уже поддерживает выдачу по `repository + VID-XXX`. При регистрации BW-XXX это необходимо учитывать: `scripts/beles.py` для BW-XXX пока формирует URL с BW-ID; downloader для таких задач нужно запускать с `VID-XXX` из `manifest.studio.video_id` и затем проверять BW manifest SHA/size. Не объявлять этот шаг полностью автоматизированным до проверки на новом видео. Без дополнительных разрешений платные сервисы не запускать.
